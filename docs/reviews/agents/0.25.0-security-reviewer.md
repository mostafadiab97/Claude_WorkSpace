# Security review — 0.25.0 (frozen commit 261801b)

Scope: the 0.25.0 diff only, as the pack names it. That covers the PDF print window (`src/main/pdf.ts`), the export
save path in `src/main/ipc.ts`, `validate.exportRequest`, reading the Word template (`src/modules/workspace/exporting.ts`)
and HTML/XML escaping in `src/modules/import-export/document.ts`. Line numbers are from the frozen commit.
`document.ts` changed on disk during the review, so the lines after 130 are now about 5 lower. The two regex lines are
now 198 and 222. Evidence: reading the code, plus one timing script on hostile template XML (results under S-01). Terms:
*zip bomb* = a small zip that unpacks to gigabytes; *quadratic* = time grows with the square of the input size;
*external relationship* = a link inside a .docx that Word follows to a remote address when the file opens.

| S-01 | src/modules/import-export/document.ts:193, :217 | Medium | F: `fillPart` (`/<w:p[ >][\s\S]*?<\/w:p>/g`) and `styleIds` (`<w:style\b…[\s\S]*?<w:name …`) take quadratic time on a template that has opening tags but no closing ones. | S-02 | src/modules/workspace/exporting.ts:50; document.ts:226-233 | Medium | F: there is no size limit on the template file or on its unpacked parts. ## Questions for the owner

1. Word templates that point to remote content (S-03): should reqochet **refuse** them (recommended: the export stops

2. Largest Word template you expect teams to use? Recommended limit: 50 MB per file (S-02); real templates with logos
   are usually under 5 MB.

## Checked, nothing found

- Template name from the window: `validate.exportRequest` refuses `/`, `\` and `..`. In addition, the core matches the name only against the `readdir` list (exporting.ts:48), so a path can never reach `join`.
- `validate.exportRequest`: format list closed (7 values); title ≤ 200 characters; columns ≤ 500 entries; `traceTable` only `true`; template only when it is a string ≤ 120 characters.
- Save location: comes only from the system save dialog; file name fixed (`requirements-<date>`); the document title never becomes a file name.
- HTML export escaping: every value goes through `esc` (title, headings, attribute names and values, trace rows, language, meta). `linkIds` escapes first and then wraps only `[A-Z0-9-]` IDs. `mdToHtml` escapes before adding `<b>`/`<code>`. The inline search script contains no data. No images or remote URLs can be produced.
- Word export escaping: block content goes through `run()`/`xmlEsc`. Inline placeholders are escaped on both paths of `fillPart` (same run, and the split-run path decodes and then re-escapes). Style ids from the template go through `xmlEsc`.
- PDF window settings: `javascript: false`, `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false`, no preload, `show: false`. It uses the default session, whose permission handler allows only clipboard writing (index.ts:109-114). The window is destroyed and the temp folder removed in `finally`. `mkdtemp` gives a random, private folder.
- IPC: `exportItems` validates with `v.exportRequest`; `wordTemplates` takes no input; `exportCompare` keeps its format list without the new formats.
- Libraries: no new dependency; `jszip` 3.10.2 was already used (MIT/GPL dual licence, so MIT allows commercial use, NFR-07). I did not run `npm run check:deps`, because the lock file is unchanged for this diff.
- Workflows and secrets: no workflow file in the diff. The changed files contain no tokens or keys (read in full or around the changes). gitleaks runs in CI.
