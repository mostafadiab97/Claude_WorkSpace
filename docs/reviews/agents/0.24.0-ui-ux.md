# 0.24.0 UI/UX review: Theme editor (commit d8877f7)

Scope: Settings → Theme editor (`ThemeEditor.tsx`, CSS at `styles.css:5181-5300`). I looked at the two light screenshots (`e2e/out/theme-editor-0-colours.png` and `-1-changed.png`). Dark, Ember and Arabic RTL are judged from the code only (I). Accessibility is included: keyboard order, labels, focus, contrast and colour-only meaning.

## Questions for the owner

1. Should the technical key names stay visible (for a developer) beside friendly names, or be replaced by friendly names only (U1)?
2. Should the sample box show the chosen mode (Light, Dark or Ember), even when the app is in another mode (U6)?

## Checked, nothing found

- Tabs: roles, arrow-key handling, selected state and focus ring are correct (`ThemeEditor.tsx:140-147`, `styles.css:5286`).
- Sticky action bar: stays in reach and has an opaque background plus a top border (`styles.css:5292`).
- Sample box is `aria-hidden` and its buttons are out of the tab order.
- All colours, sizes and spacing in the new CSS come from `--rm-*` variables (no hex found in `styles.css:5181-5300`).
- Logical CSS properties only; no left/right found in the new block.
- Status messages: `role=status` for success, `role=alert` for errors and the contrast warning.
- Screenshot 1: the changed row, the changed word, the tint and the active Reset are all visible; the live preview of primary works (nav item turns magenta).
