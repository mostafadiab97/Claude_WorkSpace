## Findings

| ID | Severity | Failing test | What it shows |
| --- | --- | --- | --- |
| QA-01 | Medium | `keeps underscores inside words…`, `keeps underscores in bare links…`, e2e `the Text cell keeps underscores in signal names` | `plainText` (table Text column) treats `_x_` as emphasis everywhere: `SIG_BRAKE_REQ` → `SIGBRAKEREQ`, `https://example.org/a_b_c` → `…/abc`. Markdown (and the editor preview) keeps underscores inside words. Embedded teams use such names constantly, so the table shows wrong text. Fix idea: only strip `_…_` when not between word characters. |
| QA-02 | Medium | `a label problem elsewhere in schema.yaml (item type) does not stop the user from saving fields` | `writeSchemaFields` refuses to save when the *whole* schema has any problem. Label problems are documented as "reported and left out", but one bad label on an item type (`labels: { Arabic: … }`) blocks every field edit in the window, with an English technical message. The check existed before; the new label rules make it much easier to hit. Fix idea: only refuse problems in `fields`, or problems that existed before the edit. |
| QA-03 | Low | `the export offers the visible columns in the table order (No. first…)` | `shownColumnKeys` now uses `defaultOrder`, which has no `number`; the Columns menu also saves orders without `number`. So the export puts the outline number after all fields — before 0.15 it came first, and the table still shows it first. |
| QA-04 | Low | `never suggests a value that is only spaces`, `the same name with a trailing space is suggested once` | `fieldValues` suggests `'   '` and lists `Ann` and `Ann ` as two people. Values are stored untrimmed. Fix idea: `TRIM(value)` in the query (or trim on save). |
| QA-05 | Low | `a choice named like a built-in object property shows itself, not program code` | `optionLabel` reads `optionLabels[lang][value]` from a plain object: a choice named `constructor`/`toString` without its own label returns a function, and the table cell shows `function Object() { [native code] }`. Fix: `Object.hasOwn` check. Unlikely names, but cheap to fix. |
| QA-06 | Low | `in Arabic every part is translated and joined with the Arabic comma` | The status-bar filter summary joins parts with `, ` in Arabic too; Arabic uses `، `. Wording, could go to the Arabic wording review. |
| QA-07 | Low | `row keys are unique when two files share an ID and both carry the same broken link` | Problem row keys are `i-<id>-<path>-<message>`; two files with the same ID (happens after merges, D-09) with the same broken link give identical keys → React key warning, rows may be merged. Key pattern predates 0.15 but the panel was rebuilt. Fix: add the list index. |
| QA-08 | Low | `refuses language keys that schema.yaml would reject…` | `validate.fieldDefs` accepts any label key (`Arabic!`), which the parser then rejects, so the save fails late with a raw message. Use the parser's language pattern in the validator. |
| QA-09 | Low | `an empty "labels:" key is treated like no labels…` | `labels:` with nothing after it (YAML null, a common half-typed state) is reported as a problem; with QA-02 this blocks field editing. Treat null like missing. |
| QA-10 | Info | `refuses Windows device namespaces…` | `importPath` accepts `\\.\pipe\x.csv` and `\\?\GLOBALROOT\…\x.csv` as "UNC" paths. Only reachable from ReqMan's own window; worth refusing `\\.\` and `\\?\` for robustness. |
| QA-11 | Info | `caps the number of languages in optionLabels…` | `optionLabels` has no cap on the number of languages (each inner map is capped at 1,000). Robustness only. |
| QA-12 | Info | `does not cut a character made of two UTF-16 units in half` | `middleEllipsis` can split an emoji (surrogate pair) in a path, showing `�`. Rare in folder names. |

Not failing, noted for the builder:

- `checkRepository` (repository-store) reports broken links with path `links[i].target`; the panel groups by exact
  path and would put those under "Other". Today `RepoInfo.issues` comes from the index (`path: 'links'`), so it is
  not visible — only if that source ever changes.
- A field renamed or an enum choice renamed in the window keeps its old Arabic label / old `optionLabels` key
  (stale translation). Product question: warn, or drop the label on rename?
- The Text column shows raw HTML from item text as text (e.g. `<img src=x …>`); harmless (React escapes it), but noisy.
