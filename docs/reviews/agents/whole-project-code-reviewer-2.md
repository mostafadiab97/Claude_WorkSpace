# Whole-project code review, part 2 of 3: the window (renderer)

**Scope.** Commit `752a435` (HEAD). My area is `src/renderer/`: `app/App.tsx`, the three screens, every
`workspace/` component, `workspace/screen/*`, `workspace/table/*`, `components/*`, `lib/*`, `theme/*` and
`styles.css`. I also checked that the UI structure table in `docs/ARCHITECTURE.md` and the screen descriptions in
`docs/USER-GUIDE.md` match the code. The core modules (part 1), `src/main` and import-export (part 3), security and
the Arabic wording are not repeated here. `npm run check` is green: 48 test files, 411 passed and 2 skipped, coverage
above the floor. Coverage is measured only for `src/modules` and `src/shared` (`vitest.config.mts:14`), so the
renderer components have no coverage number. Everything below comes from reading the code and from grep commands I
ran. I changed no repository file except this report. F = checked (the line or a command proves it); I = inferred
from reading.

Terms used: *dirty* = the editor has unsaved edits. *dataVersion* = the counter the workspace raises after every
change, which reloads the table, the editor, the history and the Git state. *Tidy* = before a push, the core rewrites
the order keys of the siblings of moved items (`workspace.ts:180-204`).

## Questions for the owner

1. **Closing a project with unsaved edits (CR2-01):** should the ✕ ask "Save and continue / Discard / Keep editing",
   like switching items? Recommended: yes, the same question.
2. **Push while an item has unsaved edits (CR2-03):** (a) Push is disabled until you save or discard, as Pull is today
   (recommended: simple, nothing surprising), or (b) Push saves the open item first.
3. **Where a new item goes (CR2-18):** the guide promises "next to the selected item", but the app puts it at the end
   of the top level. (a) Keep the app as it is and correct the guide (recommended for now; children already have
   "+ Child…"), or (b) place it after the selected item.

## Checked, nothing found

- Theme tokens: no hex/rgb/hsl in renderer code (`tests/theme-tokens.test.ts` green). Fonts and radii use `--rm-*`. Only 1-3 px fine-tuning paddings and the brand clear space are written as raw numbers.
- Logical CSS: no `margin/padding/border-left/right`, `left:`/`right:` or `text-align: left/right` in `styles.css` (grep). The only physical position is RowMenu's inline `left` (CR2-11). Column resize and the editor splitter flip in RTL.
- Texts: every `.tsx` text comes from `T` (`tests/ui-texts.test.ts` green). The only module-level reference, `KIND_LABEL = T.compare.kinds` (ChangesView.tsx:15), points at a nested object that `setLanguage` updates in place, so it follows the language switch. Memoised column labels depend on `useLanguage()`.
- `window.reqochet` only: no Node, Electron or `modules/` imports in the renderer (ESLint green). Item text preview: raw HTML is escaped and only https/mailto links are allowed (`lib/markdown.ts`).
- Order keys: the renderer never compares `order` values. `localeCompare` is used only to sort link IDs for display (LinksSection.tsx:50).
- Unsaved-changes guard for item switching, new item, closing the editor, branch switch (blocked), Settings (workspace stays mounted), window close (`beforeunload` + main `will-prevent-unload`) and language switch (no remount).
- Changes view: discard, revert and commit are locked while dirty. Stale comparison results are dropped by `key`, and the table stays mounted while the view is open.
- Merge window: Finish only when every part is decided; Cancel changes nothing; a stale plan returns to the Git bar.
- Flat-list paging: a generation counter drops answers from an older query. Tree loading: paging per parent with "Show more", a loop guard in `treeRows`, and the drop-zone rules that refuse descendants (tested in `tests/ui`).
- Feature switches (`lib/features.ts`) and session state (`lib/sessionState.ts`): subscriptions are cleaned up and nothing holds texts.
- ONBOARDING renderer section and first-change steps match the code (preload picks up new channels by itself).
