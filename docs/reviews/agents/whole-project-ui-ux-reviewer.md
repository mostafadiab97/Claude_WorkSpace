# Whole-project review — UI/UX reviewer (including accessibility and right-to-left)

Scope: the 40 screenshots in `e2e/out/` (I opened about 15: empty repository, table and editor, dark, Arabic, pull decision, suspect link, Changes, Settings, Fields, branches, export, Excel import check) and the renderer code behind them. I did not repeat what `0.14.5-ui-ux.md` and `0.16.0-ui-ux.md` settled, nor the code defects in the other whole-project reports. The focus is a pilot team of about 50 engineers who are new to the tool, many coming from DOORS/Jama. F = checked in a screenshot or the code, I = likely but not run. Screenshots were not regenerated. Start screen, Merge, Suspect dialog and Links section were checked only through code and text.

## Questions for the owner

1. Should the Changes counter in the top bar count requirements (items and links) instead of files? (UX-W05)
2. Is a "Coming from DOORS or Jama?" guide page wanted before the pilot, or after the pilot's first feedback? (UX-W25)
3. Should keyboard access to every action be a requirement for the pilot (it is a company-wide accessibility rule in many embedded-device firms)? If yes, UX-W03/W04/W20 move up. 

## Checked, nothing found

- Dark mode versus Light: the same layout, readable text, the primary blue and the success/danger colours keep their meaning (07-dark, 08-settings-wide, health-0-note-dark/light).
- Visible keyboard focus: `styles.css:38-41` sets a global 2 px focus outline from the theme; inputs, resize handles and menu items have their own focus styles.
- Dialog semantics: Export, Fields, Suspect links use `role="dialog"`, `aria-modal` and `aria-label` (grep).
- Table semantics: `treegrid`/`grid` role, `aria-rowcount`, `aria-expanded`, `aria-level`, `aria-sort` on headers, resize handles with arrow-key support and labels.
- Tree keyboard: Up/Down/Left/Right navigation and expansion work (`ItemTable.tsx:165-190`).
- Merge decision dialog: left red bar is paired with the word "Title" and the explicit before text; the choice is not carried by colour alone.
- Import wizard: the step indicator has a check icon and the number, the current step is bold (not colour alone).
- Settings pages and sticky Back bar: layout, labels and grouping consistent; the left menu is reachable by keyboard.
- Floating notes: coloured and role-tagged (`role="status"`/`alert`), text states success/failure.
- Not repeated: items of `0.14.5-ui-ux.md`, `0.16.0-ui-ux.md` and the code defects of the other whole-project reports.
