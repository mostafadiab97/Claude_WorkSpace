## Checked, nothing found

- SQLite tables: no table change since `FORMAT_VERSION = '5'` (`git diff ff6da7c HEAD` on sqliteIndex.ts, no DDL lines); the cache is dropped and rebuilt on a format change (`prepareTables`).
- Order keys: compared byte-wise everywhere (`<`, SQLite BINARY on `ord`); no `localeCompare` on order keys (`grep`).
- Queue: every write and Git action in `workspace.ts` is wrapped in `q`/`qr`; no queued call is made from inside another (`publish` → unqueued `gitOps.push`, baseline → unqueued `gitOps.commit`, revert → unqueued `saveItem`); writes are refused while an old version is shown.
- ConflictError: every `writeItem`/`deleteItem` call in the product passes a revision, except CRC-01; schema writes check `schemaRevision`.
- Atomic writes: item files, schema, recent list and import memory go through `writeFileAtomic`; a file that cannot be read is never overwritten (`fileStore.ts:369`).
- Unknown header keys at the top level: kept by parse/serialize, including for fields removed from the schema; schema edits keep unknown keys and comments (fields, types, rules).
- Git command building: argument arrays, no shell; `GIT_LITERAL_PATHSPECS=1`; long path lists go through stdin or chunks; `status`, `ls-files`, `ls-tree`, `diff --raw`, `diff --name-only` use `-z`; merge commits use a temporary index and never touch the user's index.
- Index consistency: `syncPaths` after every write; a full sync after Git actions (`resyncAll`); `top`/`doc` recomputed for the touched items and their children.
- Traceability: coverage / impact / matrix answer from the index on the shown session; rule and `from` limits are applied (`MAX_RULES`, `MAX_FROM`).
- Schema parser: invalid entries are reported and left out; rules are checked against the types.
