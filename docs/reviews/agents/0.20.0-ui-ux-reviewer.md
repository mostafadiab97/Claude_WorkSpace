# UI/UX reviewer — 0.20.0 (traceability views)

Saved by the builder: the helper could not write files and answered in its message.

**Scope.** I reviewed the three new screenshots (coverage, matrix, impact), `TraceabilityView.tsx`, `RulesPanel.tsx`, the starter-rules notice, the ◌ gap mark, the status bar button and the Problems group. I also read the new CSS (`styles.css` lines 4061–4272) and the theme warning, success and border values. I did not open the Rules tab in a screenshot because none exists, so the Rules findings come from the code only. I did not run the app in dark mode or Arabic, so all dark-mode and RTL findings are from the code (I).

| ID | file:line | Severity | What is wrong (F = checked, I = likely) | Suggested fix |

| UI-01 | `TraceabilityView.tsx:87,99` | Medium | F: when a rule has 0 items, `pct` is 100 and the meter's `aria-valuenow` is 100. The bar is empty and the text says "No items", so a screen reader announces "100%". | Pass `aria-valuenow={total === 0 ? 0 : pct}`. Better, add `aria-valuetext` such as "1 of 2 covered". |

| UI-03 | `TraceabilityView.tsx:288,301`, `styles.css:4212` | Medium | F: a matrix row with no links is flagged only by amber text on the row header (`matrix__row--empty`). In the screenshot, "Show the temperature" is amber with a blank cell row. | Add a text or glyph mark, such as ◌ with an `aria-label` of "No links". | UI-05 | `TraceabilityView.tsx:296-305` | Medium | F: every link is the same ● whether the link is incoming or outgoing, or of different types. Contrast (F): the warning amber `#8f5600` on `#f6f7f9` and the dark `#f0a73a` on `#14171c` are both fine. Success `#15803d` against the border-grey track is fine as a non-text indicator.

**Questions for the owner**
1. Should the Traceability view carry its own document picker (recommended), or keep following the table's picker as it does now?
2. Should the matrix show titles in the column headers, or is the ID-only view with a tooltip acceptable for now?

**Checked, nothing found**
- Coverage tab: the heading is in text, the progress is read as "n of m covered · pct%", and the error and loading states have `role` attributes.
- Rules tab: every field has a label, and the remove button has an `aria-label` that includes the rule text.
- Matrix: the `th scope` attributes are correct, and the sticky headers and logical properties (`inset-inline-start`, `inline-size`) are in use. No hex or rgb appears in the new CSS.
- Offer notice: it uses `role="status"`.
- Impact tab (screenshot): the tree reads in order (refines → verifies), with the relation words in muted text.
- Table: the ◌ mark and the suspect marker are distinct from each other, and the status bar contrast is fine in light mode.
