## Questions for the owner

1. Which items count as "Obsolete" for coverage? The recommendation is to keep it as now (field `status`, value Obsolete) and say so in the guide. The alternative is a schema setting, e.g. `obsoleteWhen: { status: Obsolete }`.
2. "Show the gaps in the table" for one rule: should the table show only that rule's gaps (recommended), or all gaps of that type as now?

## Checked, nothing found

- `gapSql` parameter order (type, link, from…, min) matches the SQL text. Its place in `query()` keeps the order of all parameters.
- Coverage counting: incoming and outgoing, `from`, `min`, Obsolete on both ends, across documents, the document filter (the unit tests pass; I read the SQL).
- No new tables, so `FORMAT_VERSION` correctly stays '5'. `item_fields_rid` exists for `INDEXED BY`.
- Window calls: all six have a `ReqochetApi` method, a `Channels` entry, and an `ipc.ts` handler that validates its input. `query()` copies only known keys, so the window cannot pass `rules` or `required`.
- Queue: `saveSchemaRules` runs through `q()` and calls nothing else that is queued. The reads (coverage, impact, matrix) are unqueued, as the other reads are.
- `writeSchemaRules`: checks the revision (ConflictError), validates before writing, writes atomically.
- Rule parsing: `rules:` missing or null means "never decided"; a non-list is reported; defaults, duplicates and bad values are reported, not used.
- Impact: breadth first, each item once, `relates-to` left out, the limit checked before adding.
- Module boundaries: imports go through the module `index.ts` files only. Renderer: no colours outside theme tokens and no literal words were added in the files reviewed (the ui-texts test passes).
- Order: the matrix and impact sort with `compareOutline` plus byte-wise ID comparison; no `localeCompare`.
- Docs: USER-GUIDE §6 "Coverage, matrix and impact" and the ARCHITECTURE workspace row and schema line match the code. ONBOARDING needs no change.
