# UI/UX review 0.25.0 (commit 261801b)

Scope: the Export dialog (`e2e/out/docexp-1-dialog.png`, `src/renderer/src/workspace/ExportDialog.tsx`) and the three sample outputs (PDF, DOCX, HTML in `e2e/out/docexp-spec.*`) as a reader gets them. Accessibility included (keyboard, focus, labels, contrast, colour-only meaning). I looked at the screenshot once, read the dialog code by grep, read the HTML source, the DOCX XML and the PDF. Dark mode and Arabic were not in the pack's screenshots for this dialog, so they are not covered. Brand did not change.

## Questions for the owner

1. Should the PDF be exactly the Word layout (title page, contents) or stay a one-page quick print? (U1)
2. Should the HTML be allowed to carry links that are only marked by colour for the look of a clean page? I recommend always underlined. (U4)

## Checked, nothing found

- Dialog buttons: all real `<button>` elements, with a visible focus ring from the shared `.btn` style (I: shared CSS not read here); the close icon has an `aria-label`.
- Radios and checkboxes are wrapped in `<label>` and grouped in `<fieldset>/<legend>`, so screen readers announce the group and the choice.
- Error message uses `role="alert"`.
- Colours in the dialog come from theme tokens (no hex in the file, grep).
- The sample HTML has `lang`, `dir`, a viewport tag, a labelled search box, a labelled `<nav>`, and text contrast above 4.5:1 (#1b1f27 and #566070 on white).
- The PDF and DOCX body text is readable; the headings use real heading styles (Heading1), so the Word navigation pane works; the page footer "Page 1 of 1" is present.
