# UI/UX review — 4 Nov 2026 (rename version 0.16.0, frozen commit 28aef36)

Scope: what the rename version changed on screen — the brand face and name in the top bar with the "dev" mark, the
start screen with the large face and name, the loading animation (start and while a repository opens), Changes / Pull /
Push next to the branch button with questions and notes opening under them, and the notice for projects that still use
`requirements/.reqman`. Method: `docs/guides/ui-review-prompt.md`. Logo sizes, clear space and lockup rules are left to
the brand reviewer; only obviously broken things are flagged here.

Evidence: 40 own screenshots of the built app (`out/`, not rebuilt), named `<name>` below and kept in the reviewer's
scratch folder (not in the repository): a copy of the 10,005-item sandbox (still on `.reqman`, so the notice shows) with a
local remote that has a newer commit, and repositories created in the app with short, medium and long folder / branch
names, at 900, 1024 and 1280 px, Light, Dark and Arabic. The splash was held on screen by keeping the theme from loading
(it is normally too fast to catch). Behaviour that a screenshot cannot show was checked in the source and is marked "code".

## Summary

The rename looks calm and consistent in Light, Dark and Arabic: the face and name sit cleanly in the top bar, the
logos are not mirrored in Arabic, the start screen reads well, and the Git buttons next to the branch are where daily
work happens. The push question in Arabic opens on the start (right) side, as intended. Three things need fixing before
the pilot: (1) **the top bar does not shrink** — a long repository or branch name, or a repository without a remote,
pushes the Settings gear off the window and makes the whole window scroll sideways (UX16-01, Critical); (2) **the splash
is invisible when Windows is in dark mode** — white letters on the default white window (UX16-02); (3) **in Arabic the
folder-rename commit message starts with an invisible right-to-left mark** that goes into the team's Git history
(UX16-03). Quick wins: the folder notice's wording, layout and missing "done" feedback (UX16-04…06), closing result notes
when another panel opens (UX16-07), and a push question that uses the count it already knows (UX16-08).

## Findings

### UX16-01 The top bar does not shrink: Settings gear pushed out, window scrolls sideways
- **Screen / element:** top bar with a repository open (`23-topbar-fresh-1024`, `24-fresh-push-after`,
  `30-names-medium-1024`, `30-names-long-1280`).
- **Problem:** the brand, repository name, branch button, Changes / Pull / Push and the "no remote · Publish to GitHub…"
  text never shrink. With realistic names (`climate-control-unit` on `feature/JIRA-4711-door-lock` at 1024 px) the page
  is wider than the window; with longer names the gear is outside the window, so Settings, the user guide and Report a
  problem cannot be reached at all.
- **Evidence:** measured page width 1031 px in a 1024 px window and 1284 px in a 1280 px window; "Publish to GitHub…"
  breaks into three lines under the gear (`30-names-*`); with a 54-character folder and 60-character branch name the gear
  is gone (`23`), and after clicking Push the whole window scrolled about 420 px sideways — the table vanished to the
  start and an empty strip appeared at the end (`24`). Code: `.topbar__git .gitbar { flex-wrap: nowrap }`, no
  `max-inline-size` on `.topbar__repo` or `.gitbar__branch`, `.topbar__right` can shrink.
- **Proposal:**
  1. `.topbar__right { flex: none }` — the gear always stays visible.
  2. Repository name: `max-inline-size: var(--rm-size-topbar-repo)` (new token, 220px) with ellipsis; the full path is
     already in `title`.
  3. Branch button label: `max-inline-size: var(--rm-size-topbar-branch)` (new token, 200px), ellipsis in the middle is
     not possible in CSS, so end-ellipsis plus `title` = full name; the branch menu's first row already shows the full name.
  4. `.gitbar__sync` ("not pushed yet") and `.gitbar__noremote` `white-space: nowrap`; when there is no remote, show
     **one** small button "Publish to GitHub…" instead of disabled Pull + disabled Push + "no remote" + link (tooltip on
     the button: the existing `noRemote` text).
  5. Below 1100 px the button labels may drop to icons with tooltips (optional, M).
  6. An e2e check: with a 60-character branch name at 1024 px, `document.documentElement.scrollWidth === innerWidth` and
     the gear is inside the window, in English and Arabic.
- **Severity:** Critical · **Effort:** S (1–4), M (5) · **Type:** Layout

### UX16-02 Splash is invisible with Windows in dark mode; serif "Loading…" on a white flash
- **Screen / element:** splash at start (`01-splash-a`, `20-splash-system-dark`).
- **Problem:** the splash runs before the theme is loaded. It picks the logo by the Windows colour mode, but the window
  background is always the default white, so in dark mode only the two coloured dots float above "Loading…". The label
  is in the browser's default serif font, black, with no space under the logo, and a user who chose Dark in the app
  (Windows in Light) gets a white splash and then a flash to dark.
- **Evidence:** `20` shows only a red and a green dot; `01-splash-a` shows "Loading…" in Times touching the logo. Code:
  `.splash` sets no background; `BrowserWindow` has no `backgroundColor`; tokens (`--rm-*`) are not set yet, so
  `gap: var(--rm-space-md)` resolves to 0.
- **Proposal:** the main process already reads `config/theme.json` and the user's saved mode: create the window with
  `backgroundColor` = the theme's page background token for that mode and `show: false` until `ready-to-show`; give the
  renderer the saved mode at start (preload argument or query parameter) so the splash uses the right logo; set the
  initial `--rm-*` variables before the first paint (e.g. the main process inserts the token CSS on `dom-ready`), so the
  label uses `--rm-font-family-base`, `--rm-color-text-muted` and `--rm-space-md`. No colours in renderer code.
- **Severity:** High · **Effort:** S–M · **Type:** Dark mode / Visual

### UX16-03 Arabic: the folder-rename commit message starts with an invisible character
- **Screen / element:** "Update this project" in Arabic → Git history (`32-ar-after-update-folder`).
- **Problem:** commit messages written by the app come from the texts file; in Arabic every text gets an invisible
  RIGHT-TO-LEFT MARK (U+200F) in front. The English commit message "Rename the project folder .reqman to .reqochet
  (reqochet)" is therefore stored with that mark. It goes into the shared history, looks odd in other tools, and breaks
  searches such as `git log --grep "^Rename"`.
- **Evidence:** `git log -1 --format=%B | od -c` → `342 200 217 R e n a m e …`. Code: `marked()` in
  `src/shared/text-ar.ts`; `T.wsMsg.folderRenamedCommit` used in `src/modules/workspace/workspace.ts:110`.
- **Proposal:** commit messages are written in English for the whole team (as Git's own merge messages are), taken from
  `en` directly, or `commitFiles` strips a leading U+200F. A unit test: no commit message the app writes starts with
  U+200F. (Also reported to the code reviewer's area; listed here because it comes from the language switch.)
- **Severity:** High · **Effort:** S · **Type:** RTL / Wording

### UX16-04 "Update this project" gives no feedback
- **Screen / element:** folder notice → "Update this project" (`32-ar-after-update-folder`).
- **Problem:** one click makes a commit; the notice just disappears and only the number on Push changes (3 → 4). The
  user does not know whether it worked, that a commit was made, or that pushing is the next step.
- **Evidence:** screenshot 3 s after the click: no note, notice gone. Code: `renameFolder()` sets no success note.
- **Proposal:** show the green result note under the Git buttons: **"Folder renamed and committed. Push it when your team
  uses reqochet."** with a "Push" button in the note (same pattern as "Commit and push"). No confirmation dialog needed —
  "Undo last commit" in Changes already undoes it; mention that in the guide.
- **Severity:** Medium · **Effort:** S · **Type:** Interaction / Feedback

### UX16-05 Folder notice wording is vague and sounds like a threat
- **Screen / element:** folder notice above the table (`05-sandbox-light-1280`).
- **Problem:** "Update it to reqochet" does not say what changes; "Colleagues need reqochet to open the project after
  that" reads as a warning with no action. It also does not say that items and links stay unchanged — the first thing a
  team lead will worry about.
- **Proposal (English):** "This project uses the old folder name requirements/.reqman. reqochet can rename it to
  .reqochet in one commit — your items and links stay as they are. Push the commit when everyone on the team uses
  reqochet: ReqMan cannot open the project after that." Buttons: **"Rename folder"** (primary) · **"Not now"**. Tooltip
  on "Not now": "Asks again the next time you open this project."
- **Severity:** Medium · **Effort:** S · **Type:** Wording

### UX16-06 Folder notice layout: buttons stack, text runs the full width, looks like body text
- **Screen / element:** folder notice (`05-sandbox-light-1280`, `05-sandbox-light-1024`, `12-sandbox-dark-1280`).
- **Problem:** in English the two buttons wrap into a column ("Update this project" above "Later") at both widths;
  the text runs ~1,070 px per line; the notice has the page background with no frame or icon, so it does not read as
  "something to decide" and differs from the framed blue notes used elsewhere.
- **Proposal:** `.folder-notice .actions { flex: none; flex-wrap: nowrap }`; text `max-inline-size: 90ch`; background
  `color-mix(in srgb, var(--rm-color-surface) 90%, var(--rm-color-primary))`, `border-inline-start: 3px solid
  var(--rm-color-primary)`, padding `var(--rm-space-sm) var(--rm-space-lg)`; an "ⓘ" before the text in
  `--rm-color-primary`. Same look as the info notes (`.gitbar__notice--info`).
- **Severity:** Medium · **Effort:** S · **Type:** Layout / Visual

### UX16-07 Result notes stay over the toolbar and the Changes header while other panels open
- **Screen / element:** note under the Git buttons (`07-push-refused-note`, `08-pull-result`, `09-branch-menu`,
  `10-changes`).
- **Problem:** the note covers Filters / Columns / Import for 9 s; when the branch menu or the Changes view is opened
  in that time, the note stays — the branch menu and the note overlap, and in Changes it hides the "Changes" selector
  and cuts the "Commit" heading to "ommit".
- **Evidence:** `09` (menu and note on top of each other), `10` ("ommit"). Code: `setTimeout(onDismiss, 9000)` in
  `GitPanels.tsx`; the push question already closes when another dialog opens, plain notes do not.
- **Proposal:** close the current note when the branch menu, Changes, Settings, a toolbar pop-up or a dialog opens;
  success notes 5 s, error notes stay until ✕. Better (M): short one-line results ("Pulled. No items changed.",
  "Pushed.") appear inline in the empty top-bar space after Push, as status text with a ✓ in `--rm-color-success`; only
  multi-line results and errors use the floating note.
- **Severity:** Medium · **Effort:** S (closing) / M (inline) · **Type:** Interaction

### UX16-08 Push question: placed under the branch button, wording ignores what the app knows
- **Screen / element:** "Pull first?" question (`06-push-question`, `31-ar-push-question`).
- **Problem:** the question starts at the branch button, not under Push, with no pointer, so it is not obvious which
  button it belongs to. The app already shows "Pull (1)", yet the question says "Get what others pushed first? Pushing
  fails when GitHub has commits you do not have yet." — a hypothetical. The refused-push note then says "The remote …",
  a second word for the same thing.
- **Proposal:** align the question's start edge with the clicked button (or a small pointer to it). Wording when the
  count is known: **"GitHub has 1 commit you do not have. Pull it first, then push?"** · buttons "Pull, then push" (primary)
  · "Push anyway" · ✕. Refused-push note: "GitHub has commits you do not have yet. Pull first, then push again." Use
  "GitHub" (the term used everywhere else) instead of "the remote".
- **Severity:** Medium · **Effort:** S · **Type:** Wording / Layout

### UX16-09 Opening a repository shows the name three times
- **Screen / element:** start screen while opening (`04-opening-0`).
- **Problem:** while the sandbox opens, the hero keeps its large face (now "thinking") and name, the loading animation adds
  a second large name below the buttons, and the top bar has a third. Two busy signs at once (thinking eyes and bouncing
  dots) compete; the disabled buttons look like a broken page.
- **Proposal:** one busy sign: while opening, the hero's name logo is replaced in place by the loading animation (same
  240 px width) with the label under it, and the separate `.start-opening` block is not shown; or the start page is
  replaced by a centred opening view (loading animation + label) until the repository is open. Leave the face/name sizes
  to the brand reviewer.
- **Severity:** Medium · **Effort:** S · **Type:** Visual / Feedback

### UX16-10 The "dev" mark reads like part of the path ("dev / sandbox")
- **Screen / element:** top bar (`05-topbar-light`, `12-topbar-dark`, `13-ar-sandbox-dark`).
- **Problem:** the mark sits between the name and "/ sandbox" with equal gaps, so it reads as a folder: "dev / sandbox".
- **Proposal:** keep the mark tight to the name (`--rm-space-xs`) and separate the repository with a larger gap
  (`--rm-space-md`) and a vertical divider (`border-inline-start: var(--rm-shape-border-width) solid var(--rm-color-border)`)
  instead of "/". Exact placement: brand reviewer.
- **Severity:** Low · **Effort:** S · **Type:** Visual

### UX16-11 Settings shows "reqochet", the top bar shows the dev tool
- **Screen / element:** Settings → Environment and versions, App line (`11-settings`, `11-settings-env-dark`).
- **Problem:** the App line says "reqochet 0.15.2" (from the theme's brand name) while the top bar wears "dev"; when the
  owner has both tools installed, the one place he checks the version does not say which tool it is.
- **Proposal:** the App line uses the app's own name: "reqochet-dev 0.16.0 · Electron … · …" (`appInfo.name`). (The
  frozen commit still says 0.15.2 — the version bump of the release step.)
- **Severity:** Low · **Effort:** S · **Type:** Wording

### UX16-12 Start screen: the brand block pushes the recent list down for daily users
- **Screen / element:** start screen (`02-start-light`, `21-fresh-confirm-init`).
- **Problem:** for someone opening the app every day, "Recent repositories" is the main target; the 88 px brand block plus
  the headline put it at ~375 px, and the name is already in the top bar.
- **Proposal:** when the recent list is not empty, a smaller brand block (face 56 px, name 160 px — above the 100 px
  minimum) or the recent list right under the buttons. Recommendation: smaller block; final sizes by the brand reviewer.
- **Severity:** Low · **Effort:** S · **Type:** Layout

### UX16-13 Pressed "Changes" button barely differs from the others
- **Screen / element:** top bar with the Changes view open (`10-changes`).
- **Problem:** `btn--active` on Changes is only a slightly darker border; the user cannot tell at a glance that the
  table is hidden behind the Changes view.
- **Proposal:** pressed state: background `color-mix(in srgb, var(--rm-color-surface) 85%, var(--rm-color-primary))`,
  border `var(--rm-color-primary)`, text `var(--rm-color-primary)`; the same for the open branch button.
- **Severity:** Low · **Effort:** S · **Type:** Visual / Accessibility

## What works

- Light, Dark and Arabic start screens are clean; the face uses the dark tile in Light and the white tile in Dark; logos
  are not mirrored in Arabic (`02-*`, `03-*`).
- Arabic mirrors the new top bar correctly; the push question opens on the start (right) side and its buttons read in the
  right order (`31`); the Arabic notice fits on one row with its buttons (`13`).
- Settings pages and Back look as in 0.15.x; nothing in them broke with the rename (`11-*`).

## Quick wins

- UX16-01 (1–4, 6) gear always visible, names truncated, one Publish button, an e2e width check.
- UX16-03 English commit messages without the right-to-left mark.
- UX16-04 a result note after the folder rename.
- UX16-05 notice wording.
- UX16-06 notice buttons on one row, framed like the info notes.
- UX16-07 close notes when another panel opens.
- UX16-08 push question wording and position.
- UX16-09 one busy sign while opening.

## Open questions

1. **Short Git results in the top bar instead of a floating note (UX16-07)?** Recommendation: yes for one-line successes;
   errors and questions keep the floating note.
2. **Folder rename: one click (with undo) or a confirmation first (UX16-04)?** Recommendation: one click plus a clear
   result note — it is a normal commit and "Undo last commit" exists.
