# Performance report — 0.19.0 (commit 2c91787)

Scope: the three new costs of 0.19.0 — (1) `openVersion` / `closeVersion` (an old version shown in the table, own temporary
index) at 10,005 and 50,000 generated items (10 documents, 301 commits); (2) the main column with the item's full text
instead of the preview (`brief: false`: tree `fetchAll`, pages, flat list); (3) the Changes view continuous list with
10,005 changed items, driven in the real built app (Electron under xvfb, software rendering). Scripts are in
`/tmp/claude-0/perf-0.19/` (`ver.mjs`, `prof.mjs`, `rq.mjs`, `crash.mjs`, `full.mjs`, `cmp.mjs`, `app.mjs`, `app2.mjs`);
the builder may copy them to `tools/perf-qa-0.19-*.mjs`. Data layer = the real `createWorkspace` with a key-aware
`openIndex` like `composition.ts`; event-loop lag measured with a 10 ms timer. Linux container, Node 22, Git 2.43; this
machine is noisy (the same parse loop took 5.4 s in the 0.18.0 report and 10.5 s today), so read times as +-50 %.
Windows start-up of Git is slower, so Git-heavy times are lower bounds. No product file was changed. The generated items
have a text of only 99 characters on average, so for the text questions I also built a 10k copy where every text is
about 2,000 characters (about half a page; `long10`).

Targets: query < 150 ms at 10k and < 300 ms at 50k (`tests/perf.test.ts`); first index < 60 s / < 240 s; for user
actions no written target — I treat > 1 s as "feels slow", > 5 s as "looks hung".

## Checked, nothing found

- `closeVersion` removes the database, the write-ahead log and the shared-memory file; opening version B while A is shown removes A; closing the repository removes it (cache dir listing after each step).
- Memory while a version is open: no growth over five open/close cycles at 10k and 50k.
- Reading in a shown version after the open: pages, text search and `getItem` are fast (see table).
- Paging and per-level fetches with full text (100 rows): 0.24 MB, same time as brief.
- `getGitState` with 10,000 changes: 0.3–0.4 s, event loop not blocked.
- Left list of the Changes view: capped at 400 entries (`SHOW`), 401 `li` in the DOM, no growth.
