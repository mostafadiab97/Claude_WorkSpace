## Checked, nothing found

- csv.ts: valid RFC 4180 inputs run: short row with multi-line last cell, CRLF, empty trailing cell, escaped quotes inside, semicolon separator, quote at end of file, empty line after a short row, the 0.16.3 list case (middle column and first column) all parse correctly. Only CR-1 and CR-2 failed.
- xlsx.ts sheetRows: `cell.master` is the real master Cell object (ExcelJS cell.js 190-194: a merged cell returns `_value.master`, an unmerged one returns `this`), so `cell.master !== cell` is reliable; master cells keep `isMerged` true and are read; vertical merges leave the lower cells empty, as intended. `updateXlsx` does not use `sheetRows` (uses `getCell`/`lastRow`), so it is not affected.
- itemOps.ts: `revision === null` (new item) skips the check; `deleteItem` check comes before the children check and before any write; no queued call inside another.
- itemFile.ts readStructure: result for `serializeItem` output (14 shapes, CRLF is stripped per line) equals the full parser's id/parent/order wherever it returns non-null; null always falls back to the full parser, so the strictness cannot lose data.
- merge.ts: both sides removed, one side removed and other unchanged, and `confirmed`-only changes do not resurrect a link (read the loop; no test run).
- structure.ts: `queryAll` pages by 10,000 with a tie-break on `i.id`, so pages are stable; `orderAfter` and `siblings` now cover groups above 10,000 items. (Duplicate IDs would tie, but they are blocked elsewhere.)
- Texts: `tooWide` and `idInTwoFiles` exist in text.ts and text-ar.ts (compiler enforces).
