# Whole-project review — security reviewer (commit cf0cc3c, 5 Nov 2026)

Scope: the core process (`src/main/`, `src/preload/`), Git command building (`git-adapter`, Git calls in `workspace`),
file paths (`safe-files`, `repository-store`), import/export parsing (`import-export`, `src/main/importFiles.ts`), the
updater, both workflows, `build/installer.nsh`, `electron-builder.yml` and the libraries. The earlier check
(`docs/reviews/done/2026-11-03-security-check.md`, v0.14.1) was not repeated; I concentrated on `git diff v0.14.1..HEAD`
in these areas (33 files, about 500 lines: rename, legacy-data move, identity per repository, "go back to a version",
project-folder rename) and on what that check did not cover (paths built from item IDs, parsing limits, licences,
workflow token scope, installer script). Evidence: two small proof scripts run with `npx tsx` against the real modules,
`npm audit`, a licence listing from `package-lock.json`, and reading the lines named below. **F** = checked (line,
command or script), **I** = inferred. Terms: *path escape* = a file name that climbs out of its folder with `..`;
*device path* = a Windows name like `\\.\pipe\x` that reaches a device or pipe instead of a file; *UNC path* = a
network address `\\server\share\…` (opening one makes Windows send the user's sign-in hash to that server).

## Questions for the owner

1. **SEC-05 licence:** one small library inside the Excel import (`buffers`, about 300 lines, from 2011) has no licence
   text. Options: (a) **replace or override the part of the Excel library that pulls it in** (recommended — keeps
   NFR-07 clean before a commercial product); (b) accept it for the internal pilot and fix it before any sale.
2. **SEC-07 network files:** should a file dropped onto the import window be allowed to come from a network share
   (`\\server\share\…`)? Recommended: yes (teams keep Excel files on shares), while device paths stay refused.

## Checked, nothing found

- Secrets in files: gitleaks runs in CI on the full history (build.yml:28-30); no new token or key in the files changed since v0.14.1 (read).
- Electron window: `contextIsolation`, `sandbox`, no `nodeIntegration`, CSP `script-src 'self'`, new windows denied, navigation guard (index.ts:51-71) — unchanged since 0.14.1 and correct.
- Preload: exposes exactly the `Channels` table plus `pathOfDroppedFile`; no Node objects leak (preload/index.ts).
- Every `ipc.ts` handler added since 0.14.1 validates its input (`installEarlierVersion`, `saveProblemReport`, `setLanguage`, `deleteBranch`, `openImportFile`, `renameProjectFolder`, `fieldDefs` labels) — read line by line.
- Git commands: all arrays through `execFile`/`spawn`, no shell; pathspecs after `--`; branch names checked with `git check-ref-format --branch` before create/delete; pull/compare/switch names are matched against `git for-each-ref` output or resolved to a hash first; history versions are looked up in `git log` output, never passed raw.
- Git identity per repository (new in 0.15): a name like `--unset` or `--file=…` is stored as a value, not read as an option (tried with Git 2.43).
- Discard: only paths that `git status` reports are deleted (gitOps.ts:251-254); Git paths cannot contain `..`.
- Publish: `ext::` and other dangerous Git transports are refused by the address pattern (only https, ssh, file, git@).
- SQL: the index uses `?` parameters for every value from the window, including field filters (sqliteIndex.ts:357-414).
- Item text preview (`lib/markdown.ts`, marked 18): raw HTML shown as text, images as text, only https/mailto links; CSP blocks scripts.
- ReqIF reading: saxes parser, no DTD entity expansion.
- Legacy data move (0.16, legacyData.ts): copies only named settings files/folders from `%APPDATA%\ReqMan`, removes it only after a complete copy; `fs.rm` does not follow links.
- Problem-report and export save paths come from the save dialog only.
- Updater: release list read over https from api.github.com with owner/repo from `app-update.yml`; only github.com download addresses; version picked from that list, not from the window.
- Workflows: the acceptance run's real push is skipped for pull requests (build.yml:68); the push address with the token is masked in the acceptance report; release.yml does not run on pull requests.
- Libraries: `npm audit` — 0 problems in shipped libraries; 15 "moderate" in build tools only (minimatch via eslint/electron-builder), never installed on users' PCs.
- Installer: per-user, no administrator rights; removes ReqMan only through its own uninstaller and deletes the folder only when that succeeded.
