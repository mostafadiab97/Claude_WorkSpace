# Security review — 0.20.0 (v0.19.1..HEAD, commit 17b589f)

**Scope.** I looked at the traceability changes: coverage rules read from a pulled `schema.yaml`, the SQL built in `sqliteIndex.ts` (`gapSql`, `coverage`, the `gaps` filter), the six new window calls and their checks in `validate.ts`, the matrix Excel export, and how much time and memory impact and matrix use on a large or hostile repository. I also checked for secrets in the diff and for changes to libraries and workflows. I measured with scripts in `/tmp` against a 10,000-item repository made by `npm run gen:repo`; that scratch folder has been deleted. "Main process" = the Electron part that reads files and runs SQLite. While it is busy the whole window freezes, and if it crashes the app closes.

## Questions for the owner

1. Exported Excel cells that start with `=`, `+`, `-` or `@`: should reqochet mark them as text explicitly? That protects users who later edit the file, but people see a leading `'` in the cell editor. Recommended: yes, for every Excel export.
2. Very large matrices: refuse with a message, or write a list sheet instead (one row per item, its linked IDs in one cell)? Recommended: write the list sheet automatically above the limit.

## Checked, nothing found

- **Window calls:** all six new handlers in `ipc.ts` check their inputs. `saveSchemaRules` uses `coverageRules` + `str(revision)`, `getCoverage` uses `str(document, 300)`, `getImpact` uses `v.id`, `getMatrix`/`exportMatrix` use `matrixRequest` (type IDs checked by `TYPE_ID`, `query()` reused), and `starterRules` takes no input.
- **SQL injection:** all rule values in `gapSql`/`coverage` are bound as `?` parameters. Only fixed table names (`i`, `x`, `o`) are inserted into the SQL text.
- **Schema write:** `writeSchemaRules` checks the file revision (`ConflictError`), parses the result again before writing, replaces only `rules`, and writes atomically. Rule IDs from a pulled schema are limited to `[a-z0-9-]` (no log or markup injection).
- **YAML:** parsing goes through `yaml`, whose default alias limit protects against exponential expansion. The schema file has no size limit (that was already so; the new `rules` section only adds to it, see SEC20-02).
- **Impact:** `getImpact` stops at 5,000 nodes and visits each item once. On the 10k repo it took 9 ms. Its cost is bounded by the links of the items it visits.
- **Export path:** `exportMatrix` uses the existing `saveExport` (system save dialog, fixed file name, atomic write). No path comes from the window.
- **Secrets:** none in the diff (grep for token, secret, password, api key).
- **Libraries:** `package.json`, `package-lock.json` and `.github/` are unchanged in this diff.
- **Electron settings:** not touched in this diff.
- **Git/shell commands:** no new commands in this diff.
