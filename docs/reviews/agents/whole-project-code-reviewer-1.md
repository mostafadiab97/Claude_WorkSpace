## Checked, nothing found

- Workspace queue: every writing or Git method in `workspace.ts` is wrapped in `q(...)`. No queued call is made from inside another one (`revert` uses the unqueued `saveItem`, `publish` uses the unqueued `gitOps.push`, `tidyBeforePush` uses `structure.applyPlan`, merging uses `ops.state`). The only gaps are `close` (CR1-07) and `forgetRecent`, which writes a per-user file only.
- Conflict checks: `saveItem`, `deleteItem`, link edits, moves and imports all pass the revision they read. `writeItem` refuses to overwrite an unreadable file. `writeSchemaFields` checks the schema revision.
- Atomic writes: item files, schema, recent list and import memory go through `writeFileAtomic`, and the temp file is kept if the rename fails (see CR1-10 for the remaining gaps).
- Never force-push: `push` uses `git push` / `push -u remote HEAD:refs/heads/<branch>`. No `--force` or `+refspec` anywhere in `src/modules`.
- Pull safety: the merge is computed in memory (`merge-tree`, temporary `GIT_INDEX_FILE`, `commit-tree`, `merge --ff-only`). Pending changes that would be overwritten are refused up front and again by Git. `finishPull` refuses a stale plan (HEAD moved).
- Branch switch "take along": allowed only when the blob IDs of every changed file match on both branches.
- Byte-wise order keys: `orderKey.ts`, `structure.ts` (`<`), `importing.ts:107` (`>`), `compare.ts:278` (`cmp`). SQLite sorts `ord` with the default BINARY collation (no NOCASE on `ord`). No `localeCompare` on order keys.
- Index cache: `FORMAT_VERSION` was bumped with every table change (`git log -S` on sqliteIndex.ts: 2→3 in 0.8.0, 3→4 in 0.9.0, no table change since). Old tables are dropped on a version mismatch. Transactions roll back on error.
- Folder watcher: paths are built with `/` to match the index. A missing folder or a nameless event falls back to a full check. The watch restarts after the `.reqman` → `.reqochet` rename.
- Module boundaries: `npm run check` (ESLint module rules) is green. Modules import each other only through `index.ts` (spot-checked workspace, index-cache, repository-store).
- Schema parser: invalid entries are skipped with a message, built-in names are refused as fields, unknown `features:` names are kept.
- Order-key maths (`keyBetween`, `keysBetween`, `keyOfNumber`): read against the format description and covered by `tests/order-key.test.ts`.
- Logger (sync append, rotation, never throws), problem report, theme layering (`basename` on the logo, `wx` for the starter file), updater version maths (`compareVersions`, `revertTargets`, `OLDEST_REVERT_TARGET` = 0.16.0): nothing found.
- Self-test: works only in a temporary folder with local Git settings (no hooks, no signing) and deletes it afterwards. The user's repositories and global settings are not touched.
- `src/shared/api.ts`, `domain.ts`, `features.ts`, `guide.ts`: types match the module implementations; nothing found.
- sample-data: skimmed. Fictional data only; the benchmark writes without a revision (CR1-20).
- ONBOARDING (module table, "first change end to end", queue and FORMAT_VERSION notes) matches the code apart from CR1-24(b).
