## New findings

### UXN-01 A long parent title pushes "Change…" and "Show" out of the editor
- **Screen / element:** `35-push-question`, `36`, `37` (English), `41-ar-table-editor` (Arabic) — editor Parent field.
- **Problem:** With a parent title longer than the field ("Comfortable cabin temperature for every passenger seat") the button grows past the editor's edge; "Change…" and "Show" disappear and the text is cut by the panel. A short title already pushes "Show" to the scrollbar (`e2e:04-table-and-editor`: "Sho").
- **Evidence:** `35`: "1 REQ-A3VSR9P — Comfortable cabin temperature for every p" runs under the panel edge, no "Change…"; `41`: same in Arabic, reversed.
- **Proposal:** The closed picker button takes the free width and may shrink: `.picker__current { flex: 1; min-inline-size: 0 }`, its label `white-space: nowrap; overflow: hidden; text-overflow: ellipsis` with `dir="auto"`; "Change…" and "Show" stay `flex: none` at the end, gap `--rm-space-sm`. Full parent title in the button's tooltip. Add an e2e check: with a 60-character parent title, "Change…" is inside the editor's box.
- **Severity:** High · **Effort:** S · **Type:** Layout

### UXN-02 Arabic owner names make a ragged column in the English window
- **Screen / element:** `03`, `04`, `13` — Owner column ("محمد علي").
- **Problem:** `unicode-bidi: plaintext` with `text-align: start` aligns each cell by its own content, so Arabic names sit at the column's right edge while Latin names sit at the left — the column no longer reads as one. The same happens with Latin titles in the Arabic window (`41`: "Verify accuracy at 20 °C" ends at the column's start, OK, but mixed-language columns would be ragged).
- **Evidence:** Owner cells "محمد علي" right-aligned between left-aligned "M. Farouk", "L. Samir".
- **Proposal:** Keep the content direction but align by the window: `text-align: match-parent` on the user-content cells (the column follows the window direction; the text itself still orders correctly). Same for list rows in Changes and Problems.
- **Severity:** Medium · **Effort:** S · **Type:** RTL

### UXN-03 Outline numbers may now run into the title
- **Screen / element:** `z-numbers` (from `04-search-results`) — No. column.
- **Problem:** UX-04 was solved with `overflow: visible; text-overflow: clip` on a fixed-width column; "6.2.155.2" already touches "Battery…" with about 2 px. Five-level numbers (e.g. "4.2.170.12.3") will overlap the title text.
- **Evidence:** No visible gap between "6.2.155.2" and the title.
- **Proposal:** As proposed in UX-04: width from the longest visible number (`ch` of `--rm-font-family-mono` + `--rm-space-md` padding-inline-end), minimum 64 px, recomputed when the visible rows change; keep `tabular-nums`.
- **Severity:** Medium · **Effort:** S · **Type:** Layout

### UXN-04 Links column too narrow for its own notation
- **Screen / element:** `04`, `13` — Links column (row 6.2.7 "→2 …", row 4.2.176 "→2 …").
- **Problem:** The default width fits "→1 ←5" but not a third part (e.g. "→2 ←3 ⚠1"), so the in-link or suspect count is hidden behind "…" — exactly the part reviewers scan for.
- **Evidence:** "→2 …" in two rows.
- **Proposal:** Links cells never truncate: `white-space: nowrap; text-overflow: clip`, default width 104 px (enough for "→9 ←99 ⚠9" in the table font); if a user narrows the column, drop parts in the order ←, → but always keep ⚠.
- **Severity:** Medium · **Effort:** S · **Type:** Layout

### UXN-05 "Only on GitHub" lists the current branch
- **Screen / element:** `43-ar-branch-panel` — branch panel, after a pull left the local `main` 2 commits ahead of `origin/main`.
- **Problem:** The new heading "Only on GitHub" (UX-20) states something false: `main` exists on this PC and is the current branch, it has only diverged. A user may think the branch is missing locally, or "switch" to it.
- **Evidence:** "على GitHub فقط" section shows "main" while "✓ main" is the current branch; `git branch -vv`: `main [origin/main: ahead 2]`.
- **Proposal:** List under "Only on GitHub" only remote branches without a local branch of the same name. Show the sync state of the current branch on its own row instead: "main — 2 commits not pushed" / "GitHub has 1 commit you do not have" in `--rm-color-text-muted`.
- **Severity:** Medium · **Effort:** S · **Type:** Wording

### UXN-06 Arabic Changes view: built-in field names and commit wording
- **Screen / element:** `42-ar-changes-menu` — difference table and commit split menu.
- **Problem:** The field column and the changed-field list show "Title" in English in the Arabic window (built-in field names are not taken from the texts file there); the menu says "إيداع عنصر واحد ثم الدفع" ("commit 1 item and push") while the main button says "إيداع تغيير واحد" ("commit 1 change") — two words for the same count.
- **Evidence:** "Title" in the Field column and in the row's changed-fields cell; the two button texts.
- **Proposal:** Use the same translated names as the editor labels (العنوان، النص، النوع، الأصل …) for built-in fields in Changes, History and Compare; Arabic menu text built from the same noun as the main button ("إيداع تغيير واحد ثم الدفع"). English unchanged.
- **Severity:** Low · **Effort:** S · **Type:** RTL

### UXN-07 Arabic type names are cut in the Type column
- **Screen / element:** `41`, `e2e:language-1-arabic` — Type column ("احتياج …", "متطلب …", "حالة اخت…").
- **Problem:** The default schema has short type labels only in English ("SysReq"); in Arabic the full name is used in a column sized for short labels, so similar types cannot be told apart — the UX-03 problem returns in Arabic.
- **Evidence:** Every Arabic Type cell ends in "…".
- **Proposal:** Allow `short:` with languages like `label:` (`short: { en: SysReq, ar: … }`) and ship Arabic short labels in the default schema (wording by the translator); without a short label, size the Type column from the longest visible type name (max 160 px).
- **Severity:** Low · **Effort:** S · **Type:** RTL

### UXN-08 Appearance page: two unlabeled switches in one row
- **Screen / element:** `23-settings-appearance`, `40-ar-settings-appearance`.
- **Problem:** Language and colour switches sit side by side without labels; only the sentence above hints which is which. It is the only settings page without labelled rows.
- **Evidence:** "English | العربية" and "Light | Dark | System" in one line.
- **Proposal:** Two rows, label at start, control at end, like the Environment card: "Language" — [English | العربية]; "Colours" — [Light | Dark | System]; gap `--rm-space-md`. Keep the explanatory sentence as the card's hint.
- **Severity:** Low · **Effort:** S · **Type:** Layout

### UXN-09 The editor splitter cannot be used from the keyboard
- **Screen / element:** line between table and editor (code: `EditorSplitter.tsx`).
- **Problem:** The new splitter (UX-03) is `role="separator"` without `tabIndex`, keys or `aria-valuenow`; keyboard and screen-reader users cannot resize the editor, and no hover affordance was visible in the screenshots.
- **Evidence:** No focusable element between table and editor; nothing marks the drag line in `03`/`19`.
- **Proposal:** `tabIndex=0`, ←/→ change the width by 16 px (mirrored in Arabic), Home = default width, `aria-valuemin/max/now`; on hover and focus show a 2 px line in `--rm-color-focus` and the `col-resize` cursor.
- **Severity:** Low · **Effort:** S · **Type:** Accessibility

### UXN-10 Suspect dialog: raw Markdown in "What changed" and a footer that differs from the pull dialog
- **Screen / element:** `11-suspect-dialog`, `12-suspect-dialog-decided`.
- **Problem:** The diff shows list markers ("- No error entries…") although the editor now shows formatted text; the footer puts "Apply my choices" at the start under "Keep all / Unlink all", while the pull dialog puts counter and finishing buttons at the end — two decision dialogs, two layouts.
- **Evidence:** "- No error entries in the device log" with the dash; footer rows in `12` vs. `e2e:12-pull-decision`.
- **Proposal:** Strip Markdown markers in this compact diff (as the table's Text column does). Footer in one row: "Keep all", "Unlink all" at start; "2 of 4 decided", "Decide later", "Apply my 2 choices" (primary) at end — same order as the pull dialog.
- **Severity:** Low · **Effort:** S · **Type:** Visual

### UXN-11 Commit panel: an empty divider above the message
- **Screen / element:** `16`/`fail-changes`, `31-commit-menu-open`, `26-dark-changes`.
- **Problem:** A horizontal line sits between the panel subtitle and "Commit message" with nothing between them (left over from the removed change list), which looks like a missing section.
- **Evidence:** Two lines 40 px apart under "Only the requirements folder is committed — never your code."
- **Proposal:** Remove the empty divider; keep `--rm-space-lg` between subtitle and the message label.
- **Severity:** Low · **Effort:** S · **Type:** Visual

## Quick wins

UXN-01 (parent field shrink), UXN-02 (`text-align: match-parent`), UXN-03 (No. width from content), UXN-04 (Links never
truncates), UXN-05 (remote list without local names), and the remaining part of UX-02 (`dir="auto"` on title spans,
Changes rows, preview blocks and content selects, plus an e2e ellipsis check).

## Proposed theme tokens

None required. The fixes use existing tokens (`--rm-space-*`, `--rm-color-focus`, `--rm-color-text-muted`,
`--rm-font-family-mono`). The column widths (No. from content, Links 104 px, Type max 160 px) are layout constants in
the table code, not theme values.

## Open questions

1. **Editor footer wrapping (UX-14).** Recommended: one row — Save, Discard (when dirty), ↑ ↓, "Add child ▾" split
   button, flexible space, Delete — with ↑ ↓ moving into a "More ▾" menu below 420 px editor width. Alternative: keep
   two rows but make the split deliberate (actions row, item row) with a divider.
2. **Result notes position (UX-01).** Recommended: anchor result notes to the start of the content area below the
   toolbar so they never cover the editor header or the toolbar. Alternative: keep them at the top end but shift them
   below the editor header when the editor is open.
