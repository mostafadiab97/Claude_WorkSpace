# Code review — 0.15.0 "UI polish" (frozen commit c37313d against release d3aac31)

Reviewer: code-reviewer helper (read-only). Scope: `git diff d3aac31 c37313d` without `docs/reviews`, judged against
CLAUDE.md rules and the Decisions in `docs/reviews/agents/0.14.5-ui-ux.md`. `npm run check` on the frozen commit is
green (typecheck, ESLint, 223 unit tests, coverage floor met).

Checked and found fine: the Markdown preview is XSS-safe (raw HTML, `<script>` in tables, `javascript:` links,
attribute break-out in `href`, and images were tried, all escaped or dropped; links only open through the existing
`setWindowOpenHandler`/`will-navigate` guard); the new window calls follow the ReqManApi + Channels + validated handler
rule (`pathOfDroppedFile` is answered in the preload and kept out of `Channels`/`InvokeMethod`); `validate.importPath`
and `validate.fieldDefs` labels are bounded; `fieldValues` uses the existing `item_fields(field, value, rid)` index
(no `FORMAT_VERSION` bump needed, since the tables did not change); `config/theme.json` and `defaults.ts` agree; every new text key
exists in both `text.ts` and `text-ar.ts`; no new texts in module-level constants; new CSS uses logical properties
only and no hex/rgb.

## Findings

### CR-01 — Medium — Alt+↑/↓ is caught for the whole window, so it takes over keys that controls need

`src/renderer/src/workspace/ItemEditor.tsx:151-160`

The handler sits on `window` and runs whenever the item has no unsaved changes, wherever the focus is. Alt+↓ is the
standard Windows key for opening a focused `<select>`, and this window has plenty of them: Type, enum fields, the
"New item" list that Ctrl+N focuses (WorkspaceScreen.tsx:65 even says "the focused list still opens with Alt+↓"), and
the link-type list. Alt+↓ also opens the new field-value suggestions (`<datalist>`). With an item open, the key moves
the item among its siblings and `preventDefault()` stops the list from opening. The handler also runs while
Settings/User guide is shown (the workspace stays mounted, only `hidden`) and while a modal (suspect links, import,
merge) is open, so an item can move where the user cannot see it. Ctrl+Shift+C and Ctrl+N in
`WorkspaceScreen.tsx:51-77` act behind open modals and Settings in the same way.

Fix: skip the shortcut when `e.target` is a `select`, `input`, `textarea` or `[contenteditable]`, or sits inside
`.modal`/`[role=dialog]`, and when the workspace is hidden (pass an `active` flag, or check
`document.activeElement`). Also ignore `e.repeat` so that holding the keys does not queue dozens of moves.

### CR-02 — Medium — The table's Text column removes underscores and asterisks inside words

`src/renderer/src/lib/markdown.ts:38` (`plainText`), used by `table/columns.ts:126` and the cell tooltip

The regex `(\*\*|__|\*|_|`|~~)(?=\S)([\s\S]*?\S)\1` does not follow Markdown's word-boundary rule for `_`. Results
checked on the frozen commit: `CAN_ID_MAX and SIG_A_B` → `CANIDMAX and SIGAB`, `2*3*4 = 24` → `234 = 24`. The editor
preview (marked) shows `CAN_ID_MAX` correctly, so the table and the editor disagree. Signal and constant names with
underscores are everywhere in the pilot team's embedded requirements, so the main table would show changed
requirement text.

Fix: only strip `_`/`__` when they are not between word characters, e.g.
`(^|[^\w])(__?)(?=\S)(.*?\S)\2(?!\w)`. A simpler and safer option is to take the text from marked's lexer
(walk the tokens and join their `text`). Add `CAN_ID_MAX` and `2*3*4` to the `plainText` test.

### CR-03 — Medium — "Save and continue" skips the suspect-links review

`src/renderer/src/screens/WorkspaceScreen.tsx:498-507`, together with `ItemEditor.tsx:124` (`setReview`)

When the save changes the title, text or type and other items link to this one, `save()` sets `review` to open the
SuspectLinksDialog (O-04). The guard's `.then` then calls `setTarget(next)` straight away. That re-keys the editor
and unmounts it, so the review is gone before it can show. The links stay marked suspect, so no data is lost, but
the review step that a plain Save gives (and that the ISO 26262 pilot relies on) is skipped without a word.

Fix: let `save()` return `'saved' | 'review' | false`. When it returns `'review'`, keep `pending` and move to `next`
only after the dialog's `onDone`, or show a note that N links were marked suspect. Add an e2e step for it.

### CR-04 — Low — Upgraded users with a saved column order get ID after Text

`src/renderer/src/workspace/table/columns.ts:131-133`, `FieldsPanel.tsx:107-110`

Before 0.15, ID was always first and never part of `prefs.order`. Anyone who ever moved a column has a saved order
without `'id'`. `orderColumns` gives unknown keys `order.length + i`, so ID ends up after Text (often off-screen on
the right). The decided default puts ID just before Text. The test "a saved order keeps ID where the user put it"
only covers orders that already contain `id`.

Fix: when a saved order has no `'id'`, insert it before `'text'` (or at the decided default position) when the
prefs are loaded.

### CR-05 — Low — Git identity is now per repository: every new clone or new project asks again, and the first commit after "New project from a file" fails without notice

`src/modules/git-adapter/systemGit.ts:563-566`; `src/modules/workspace/importing.ts:166-172`

`--local` is the right call for privacy (company repositories), but it changes behaviour. A user whose name was set
through ReqMan now has no identity in each new clone or new project. "New project from a file" commits at once,
catches the failure and logs only a warning (`committed: false`). Check that the UI tells the user the import is
uncommitted and asks for name and e-mail. The Settings environment card may also still show a global identity that
no longer matches what commits use.

Fix: in the new-project flow, when there is no identity, ask before the first commit, or say clearly that the items
are uncommitted. Mention the change in the user guide and in the changelog.

### CR-06 — Low — The text preview's `role="button"` swallows Enter on links, and its label points at the wrong control

`src/renderer/src/workspace/ItemEditor.tsx:616-631` and `635-652`

(a) The preview `div` turns Enter into "edit" and calls `preventDefault()` even when the focus is on an `<a>`
inside it, so keyboard users cannot open links. Mouse clicks on a link that wraps formatting (`[**x**](https://…)`)
both follow the link and switch to edit mode, because `e.target` is the `<strong>`, not the anchor. Use
`(e.target as Element).closest('a')` in both handlers. A `role=button` that contains links is also nested
interactive content.
(b) In the edit branch, the `<label>` holds the "Formatted view" `<button>` before the `<textarea>`. A label's
control is its first labelable descendant, so the textarea loses its accessible name "Text", and a click on the
word "Text" presses the Preview button. Move the button out of the `<label>`, or use `<div>` plus
`aria-labelledby`.

### CR-07 — Low — Merge choices: `aria-label` hides the values on the new side buttons

`src/renderer/src/workspace/MergeDialog.tsx:114-128`

The yours/theirs versions are now `<button aria-label="Keep yours">` with the value inside. The `aria-label`
replaces the content, so a screen reader announces only "Keep yours / Take theirs", never the values being
compared. Drop `aria-label` (the visible "Yours"/"Theirs" plus the value make a good name) and keep `title`, or use
`aria-describedby` for the value.

### CR-08 — Low — Commit split menu stays open and usable after the message is cleared

`src/renderer/src/workspace/GitPanels.tsx:420-458`

`menu` closes only on Esc or on choosing the item. After a normal commit (message reset to `''`), or after the user
clears the message, the menu stays visible and "Commit and push" can still be clicked. The toggle is disabled but
the item is not, so an empty commit is sent and fails in the core. Clicking outside does not close it either.
Disable the item under the same condition as the toggle (`locked || !message.trim()`), close the menu on submit and
on outside pointer-down (the same pattern as the Git bar pop-over).

### CR-09 — Low — Markdown is parsed again on every editor render

`src/renderer/src/workspace/ItemEditor.tsx:631`

`renderItemText(form.text)` runs inside JSX, so it re-parses the whole text on every keystroke in Title or in any
field. That is cheap for normal items, but it adds up for long imported texts (ReqIF/Excel imports can have pages
of text). Fix: `useMemo(() => renderItemText(form.text), [form.text])`.

### CR-10 — Low — The editor splitter cannot be used from the keyboard, and a remembered width can exceed the window

`src/renderer/src/workspace/screen/EditorSplitter.tsx:42-53`

`role="separator"` has no `tabIndex`, `aria-valuenow` or arrow-key handling, so only the mouse can resize the
editor. The 70 % cap applies only while dragging: a width saved on a large monitor is loaded unchanged on a smaller
window (`load()` checks only `>= MIN`), and the table can be squeezed to nothing. Clamp in the CSS
(`min(var(--rm-editor-width), 70vw)`) or on load and resize. Add `tabIndex={0}` and ←/→ steps.
