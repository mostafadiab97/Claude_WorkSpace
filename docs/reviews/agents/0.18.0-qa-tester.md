# QA tester — 0.18.0 (baselines, history, copy ID, discard)

Saved by the builder: the helper could not write files in this session and answered in its message.
Tests: `tests/qa-0.18.0-baselines-history.test.ts` (20 tests; 6 failed on the frozen commit).

## Findings

| ID | Where | Severity | Finding (all F, checked by a failing test) |
| --- | --- | --- | --- |
| QA-01 | `gitOps.ts` push (~line 250) and `baselines.ts` | High | A waiting baseline whose tag was deleted outside reqochet makes every later Push fail with "src refspec … does not match". The marker is never cleared and `pendingBaselines` still counts it. Fix: drop waiting names whose tag no longer exists before pushing. |
| QA-02 | same | High | A baseline name already on the remote (a colleague pushed it first) makes the tag push fail. The commits do arrive, but every later Push fails too. Fix: treat a rejected tag as a message, clear or keep the marker explicitly, and tell the user the name is taken. |
| QA-06 | `systemGit.ts` `history` | Medium | The history list throws "current branch 'main' does not have any commits yet" in a repository with no commits. It should return an empty page. Fix: catch that error or check HEAD first. |
| QA-11 | `baselines.ts` snapshot, `outlineNumbers` map keyed by `id` | Medium | In a commit where the same ID sits in two documents, both copies get the number of the last one. The test expected `Software:1, System:2` and got `Software:2, System:2`. Fix: key numbers by document plus ID. |
| QA-13 | `itemOps.ts` `renewCopyId` | Medium | Without Git, or with every copy tracked, the newest file is treated as the copy. If the original was edited later, or the real copy kept an old time (`cp -p`, unzip, sync tool), the original loses its ID. Fix: when the choice is a guess, ask the user which file is the copy. |
| QA-10 | `baselines.ts` snapshot | Low | A snapshot item whose parent is missing (parent file deleted) gets no outline number. The test expected a number as the live index gives. |

Not tested (Linux): on Windows, baseline names that differ only in case (`SRS` and `srs`) may clash, because Git
stores tags as files.
