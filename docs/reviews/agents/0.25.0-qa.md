# QA report — 0.25.0 (Word / PDF / web page export, title bar mode)

Scope: I tried to break the Word export (`fillPart`, `itemsToDocx` in `src/modules/import-export/document.ts`) with odd template XML, split placeholders, header/footer, empty project, 12 levels of depth, special characters, Arabic and 10,005 items. I did the same for the web page / PDF source (`itemsToHtml`), template lookup (`exporting.ts`, `validate.ts`) and the title bar mode call (`windowIcon.ts`, `ipc.ts`). One new unit test file holds 25 tests: `/tmp/qa-0.25/tests/qa-0.25.0-docexport.test.ts`. It is meant to be copied to `tests/qa-0.25.0-docexport.test.ts`, and I ran it against the working tree through a scratch config. 15 pass, 10 fail. Each failing test is named `DEFECT:` and asserts the correct behaviour. I did not run the real Word, the real PDF printing (needs Electron) or e2e.

Note: `document.ts` was edited by someone else at 11:09 while I worked. It gained `rtl()` and `<w:bidi/>` for the Arabic window, and its line numbers moved. My first run showed no right-to-left support in Word, and the later run shows it. The table uses the line numbers of the file as it stood when I read it. They may be off by a few lines.

| ID | file:line | severity | what is wrong (F = checked, I = likely) | suggested fix |
| --- | --- | --- | --- | --- |
| Q1 | document.ts `fillPart` (`key in inline`, `key in block`, about line 198-206) | Medium | F. A template placeholder with the name of an object property crashes the whole Word export with `TypeError: s.replace is not a function` (`{{toString}}`). `{{constructor}}` in a paragraph by itself would paste "function Object()…" into the document. The pattern `[\w.]+` allows these names. Test: "placeholder named like an Object property". | Use `Object.hasOwn(inline, key)` / `Object.hasOwn(block, key)` or `Map`s. |
| Q2 | document.ts `fillPart` (regex `<w:p[ >][\s\S]*?<\/w:p>`) | Medium | F. A self-closing paragraph with attributes (`<w:p w:rsidR="…"/>`, common in Word-made files) starts a match that swallows the next paragraph. If that paragraph has a split placeholder, the output has an opening `<w:p …/>` plus a closing `</w:p>` that never opened, which is invalid XML, so Word reports a corrupt file. A matching test passes when there is no split placeholder, so the damage is silent. | Skip self-closing tags: use `<w:p(?:\s[^>]*[^/])?>` (not ending in `/`) and handle `<w:p …/>` separately. |
| Q3 | document.ts `fillPart`, split-placeholder branch (rebuilds the paragraph from `pPr` + first `rPr`) | Medium | F. When a placeholder is split over several runs, the whole paragraph is rebuilt from text only. Fields (PAGE, NUMPAGES), tabs, line breaks, hyperlinks, bookmarks and images in that paragraph are lost. A footer such as "{{document.name}} page [PAGE]" typed in Word loses its page number. Word splits placeholders often, so this is likely in real templates. Tests: "split placeholder in a footer keeps the page-number field", "keeps a tab". | Replace only the runs the placeholder spans. Put the filled text in the first run's `<w:t>`, empty the `<w:t>` of the other runs it touches, and leave every other run as is. |
| Q4 | document.ts `fillPart`, block replacement (`return block[…] ?? ''`) | Medium | F. An empty block (empty project, no links, no baselines: `{{items}}`, `{{trace.table}}`, `{{revision.history}}`) removes the paragraph. When that paragraph is the only one in a table cell (a layout table, a "revision history" box), the cell has no paragraph, and Word treats that as corrupt. Test: "empty block in a table cell". Also removes a paragraph that carries a section break (`<w:sectPr>` inside `pPr`) (I). | If the block is empty, return an empty paragraph (`<w:p/>`) when the parent is a `<w:tc>`; keep the paragraph's `pPr` when it holds a `sectPr`. |
| Q5 | document.ts `xmlEsc` and `run` | Medium | F. Characters that are illegal in XML 1.0 (0x00-0x08, 0x0B, 0x0C, 0x0E-0x1F; for example a vertical tab or ESC pasted from a PDF into an item) go straight into `word/document.xml`, and Word refuses to open the document ("unreadable content"). The HTML page is fine, so only Word is affected. Test: "control characters in a title or text". | Strip those characters in `xmlEsc` (also lone surrogates). |
| Q6 | document.ts `styleIds` fallback `name.replace(/\s+/g,'')` | Low | F. When the template lacks a style (a template with only Heading 1-3, or no "RM Attribute Table"), the fallback id is `heading6` (lower case, and not a style of the template). Word silently uses "Normal", so the deep levels (4-6, also the trace heading) lose their heading look and the contents field drops them. No warning to the user. Test: "Heading levels deeper than a template defines". | Fall back to the deepest heading the template has (`heading N` → the highest N present), and tell the user which styles are missing. |
| Q7 | document.ts `itemsToDocx` (settings.xml, about line 237 in the first reading) | Low | F. `updateFields` is appended just before `</w:settings>`. In a real Word settings.xml that places it after `w:listSeparator`, but the schema order wants it before `w:hdrShapeDefaults`, `w:compat` and `w:rsids`. Test: "updateFields is placed where the schema allows it". Whether Word complains is I (Word is lenient in some places). If the file ends with a self-closing `<w:settings …/>` the flag is not added and the contents table is not refreshed (I). | Insert before the first of `w:hdrShapeDefaults`, `w:footnotePr`, `w:endnotePr`, `w:compat`, `w:rsids` (the right position), or handle the self-closing case. |
| Q8 | document.ts `itemsToHtml` and `mdToHtml` (headings and text) | Low | F. Arabic requirement texts in an English window are shown left-aligned (the page has `dir="ltr"`). Mixed content is left to the browser's default. Test: "Arabic requirement text in an English-window export". Word has the same gap: `<w:bidi/>` only follows the window language (I). | Add `dir="auto"` to `<h*>`, `.text p` and table cells (and `w:bidi` per paragraph by the first strong character for Word). |
| Q9 | document.ts `mdToHtml` / `mdToDocx` | Low | F. A list that follows a sentence without a blank line (`Must:\n- one\n- two`) is shown as one paragraph with raw dashes. Numbered lists (`1. x`) are never lists. In Word, `mdToDocx` strips every `**`, so "2 ** 3" loses its stars (I). | Split a block into paragraph and list parts; keep a lone `**` that has no pair. |
| Q10 | validate.ts `exportRequest` (template check `/[\\/]|\.\./`) | Low | F. A legitimate template named like `SRS..v2.docx` is rejected as "template", with a generic message. The check is stricter than needed because `readTemplate` only matches names from the directory listing. | Allow `..` inside a name; keep rejecting `/` and `\`. |
| Q11 | main/windowIcon.ts `applyWindowMode`, `index.ts:54` | Low | I. At start the window gets `windowIcon()` from the system colour. If the app mode saved earlier is Light and Windows is dark, the icon and bar are wrong until the page loads and calls `setWindowIcon`. Also `win.setIcon` is not guarded, so a missing icon file makes the call reject to the page (unhandled in `App.tsx:74` is a `void`). | Read the saved mode in the main process before creating the window; catch errors in `applyWindowMode`. |
| Q12 | `ipc.ts` `setWindowIcon` | Low | F (read). The mode is validated only when a window exists (`v.oneOf` sits inside the `if`). A bad value from a page with no window is ignored, so the validator is never exercised. Harmless. | Validate first. |

## Questions for the owner

- A template that lacks a style (Q6): should the export refuse with a message, or build the document with fallbacks and a warning on the result?
- Should Arabic text inside an English-language export be shown right-to-left automatically (Q8)? I recommend yes.

## Checked, nothing found

- Hierarchy 12 levels deep: Word headings are clamped to Heading 6 and HTML to h2..h6 (tests "12 levels", "empty project and deep hierarchy"). Never Heading 7+. HTML never uses h1 for items.
- Empty project in the built-in template: no leftover `{{`, paragraphs balanced, `sectPr` present.
- Special characters (`< > & "` and `$&`, `$1` in values) in Word and HTML: escaped; `<script>`, `<img onerror>`, a closing `</title>` in names and texts do not reach the page (only the search script exists; the print version has none).
- Arabic in Word: text, escaped characters and `• ` list marks survive; window language Arabic gives `dir="rtl"` / `lang="ar"` and `<w:bidi/>`.
- Header/footer parts: inline placeholders are filled and escaped there; block placeholders stay literal (as designed).
- A template that is not a zip: `itemsToDocx` rejects (the IPC call reports the message; I did not run the dialog).
- 10,005 items: Word and HTML build in well under the 20 s limit I set (test "10,005 items").
- Template name path traversal (`../x`, `a/b`): rejected by `validate.ts` and again by `readTemplate` (exact match on the directory listing).
- Title bar mode: `themeSourceFor` mapping (Ember = dark bar), icon choice, existing tests `window-icon-0.25`; I added no new test for it.
- Not covered: real Word and LibreOffice opening, real PDF output, e2e (no Electron run), 50k items.
