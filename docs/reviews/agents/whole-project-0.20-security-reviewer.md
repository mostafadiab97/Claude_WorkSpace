# Whole-project review 0.20 — security reviewer (commit 478cb51, 10 Nov 2026)

Scope: the whole project before the first release (pack `whole-project-0.20-pack.md`). I covered the Electron window
settings (sandbox, contextIsolation, CSP, navigation and new windows), the preload, the input checks of every
`ipc.ts` handler, file paths built from pulled data (IDs, documents, Git paths), how Git commands are built, parsing of
hostile YAML/Markdown/Excel/ReqIF/CSV files, the HTML the window renders, logs and problem reports, updater integrity,
both workflows, the installer script, `.claude/settings.json`, the libraries (`npm audit`, licences) and the privacy
check. Findings already fixed in earlier reports (whole-project SEC-01…06, 0.17–0.20) are not repeated. Earlier
findings that are **still open at this commit** are listed again at the end of the table, marked "still open", after I
checked the line again. Evidence: reading the lines named; small scripts run with `node`/`npx tsx` against the real
modules (a 17 KB Excel file, ReqIF timing, SQLite depth limit, `validate.ts` edge cases); `npm audit`; a licence list
from `package-lock.json`; a secret-pattern scan of all files and the whole Git history; the privacy check plus a scan
of the 33 tracked binary files. Scratch files were in `/tmp` and are deleted. **F** = checked, **I** = inferred.
Terms: *OOM* = the process runs out of memory and closes; *install script* = code a library runs during `npm ci`;
*device path* = a Windows name such as `\\.\pipe\x` that opens a device or pipe instead of a file.

## Questions for the owner

1. **Signed installers.** The installer and its updates are not code-signed, so an update is trusted only because it
   comes from the GitHub release. Whoever can write to that release (a stolen token, see SEC-WP2-02) can ship an update
   to every installed copy. Options: (a) **keep it unsigned for the internal pilot and plan signing before any sale**
   (recommended; free signing exists for open-source projects, e.g. SignPath's foundation, which needs a public
   project); (b) look for signing now. A paid certificate would break NFR-07's "no paid services".
2. **Agent rights (SEC-WP2-03).** Should agents be able to call the GitHub API without asking? Recommended: **read
   calls only**; anything that changes the repository or its releases asks you first.

## Checked, nothing found

- Secrets: no token, key or private-key pattern in the 425 tracked files or in the whole history (218 commits; GitHub, AWS, Slack, Google, private-key, `x-access-token:` patterns); gitleaks runs in both workflows with `--redact`.
- Privacy: `node tools/check-privacy.mjs .` passed (425 files); the 33 tracked binary files (PNG, ICO, XLSX) hold no e-mail address or listed name; the sample workbook's author field says `openpyxl`.
- Electron window: `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`; CSP `default-src 'self'; script-src 'self'` (no remote scripts, frames, or connections); new windows denied, only `https:` handed to the browser; `will-navigate` blocks every other address; one window only.
- Preload: only the `Channels` table, `reportUiError`, `pathOfDroppedFile` and the update listener; no Node or Electron objects reach the page.
- Window calls: each of the 80+ handlers in `ipc.ts` checks its input with `validate.ts` (IDs without `/ \ : ..`, 40-hex commit IDs, type IDs, order keys, length and count limits); the handlers that take raw names (branch, compare refs, item version) are matched against Git's own lists or resolved to a commit first.
- Paths from pulled data: IDs (`isSafeFileId` before every path), document names (`isDocumentName`, Unicode format characters refused), Git paths (Git refuses `..`), discard only on paths Git reports; the import source path lives in the user's settings folder, not in the repository.
- Git commands: argument arrays through `execFile`/`spawn`, no shell; `GIT_LITERAL_PATHSPECS=1`; `--` before paths; branch names through `check-ref-format --branch`; no force push; `GIT_TERMINAL_PROMPT=0`; Git is started with `-C <root>`, never with the repository as the working folder.
- SQL: every value from the window or the schema is a `?` parameter; sort keys are matched by a pattern; the field path for sorting is a parameter; full-text search words are limited to letters and digits.
- YAML: the `yaml` library's alias limit applies to item files and schema.yaml; item files over 5 MB are not read.
- XML (ReqIF): saxes does not expand DTD entities (no "billion laughs"); nesting depth errors are caught.
- Rendered HTML: Markdown with raw HTML escaped, images as text, only `https:`/`mailto:` links with escaped `href`; a formatter crash falls back to plain text; the guide HTML comes from the app's own files.
- Logs: sign-in parts of addresses masked in every log line and in problem reports; Git identity is checked and not logged; UI error messages cut to 4,000 characters.
- Updater: normal updates checked against `latest.yml` SHA-512 by electron-updater; API fallback version checked (`^\d+\.\d+\.\d+$`) and owner/repo encoded; HTTPS only.
- Libraries: `npm audit` 15 moderate, all in build and lint tools (minimatch via eslint/electron-builder), none shipped; `buffers` is gone (SEC-05 fixed); licences of all lockfile packages are MIT/ISC/BSD/Apache/0BSD/Zlib, with jszip (MIT chosen), MPL-2.0 lightningcss, CC-BY-4.0 caniuse-lite and WTFPL helpers in build tools only — all allow commercial use.
- Workflows: actions pinned by commit ID; `persist-credentials: false`; workflow-level `contents: read`; the acceptance push is skipped for pull requests; the Electron zip is checked against the locked `checksums.json`; Dependabot covers npm and actions.
- Installer: per-user, no administrator rights; the old ReqMan folder is removed only through its own uninstaller.
