## Notes (no failing test)

- **Hook wording on push:** `T.gitMsg.hook` says "refused the **commit**", even when a pre-receive hook refused a
  push (the 0.15.2 test and QA tests above both get this text).
- **Dark window, top bar (28 px):** there is no white-tile small-cut eyes file, so in dark mode `BrandFace` uses the
  full `eyes-*-light.svg` below 32 px. Light mode follows the brand rule. This is for the brand helper: the asset is
  missing, not the code.
- **Windows order of steps (not testable on Linux):** `renameProjectFolder` renames `.reqman` *before* closing the
  folder watcher that has `.reqman` open. On Windows a watched folder may refuse the rename (EPERM/EBUSY). Closing the
  watcher first (and re-creating it on failure) removes that risk. The CI acceptance run on Windows is the place to
  confirm it.
- **Read-only / locked files** in `%APPDATA%\ReqMan` cannot be simulated in this Linux container, because tests run
  as root. QA-02 shows what any copy error leads to today.
- **Company name without a logo:** a theme with `brand.name: "ACME"` and no logo shows the reqochet face and drawn
  name in the top bar. "ACME" appears only in the window title and the start-screen intro. Possibly intended (R-03);
  a question for the owner if company branding matters for the pilot.
- **Passing areas:** ReqIF/Excel across the rename, schema validation, theme fallbacks, version list and revert
  floor, the activity counter, neighbours and links in `%APPDATA%` left untouched, rename twice, staged files and
  uncommitted items kept out of the rename commit, the watcher after the rename, and the window flow (notice, Later,
  Update, thinking face during a pull).
